# Mobile — React Native Android Scanner

Phase 4 component: staff scan answer sheets with an Android phone camera.

## Current implementation

- Expo SDK 58, React Native 0.88, TypeScript, and Expo Router
- Android-only configuration with Expo Go workflow review support
- Staff Login and Scanner Home connected to Laravel authentication
- Scan Answer Sheet screen using Expo Camera
- Upload Photo screen using Expo ImagePicker and Laravel multipart upload
- Identify Applicant screen creates the applicant automatically before upload
- Temporary photo capture for workflow review; OpenCV quality analysis is deferred
- Remembered staff session stored with Expo SecureStore
- Post-capture screens are implemented one at a time after phone review

## Run with Expo Go

Install dependencies and start Metro:

```powershell
cd mobile
npm install
npx expo start --clear
```

Open the project in Expo Go and review the workflow screens. Allow camera access
when prompted. The Capture screen provides a live camera preview, framing guide,
and temporary photo capture. Live brightness and sheet-alignment analysis will
be added later with the Android development build.

## API configuration

Copy `.env.example` to `.env.local` and set the Laravel API base URL:

```dotenv
EXPO_PUBLIC_API_URL=https://your-api-host.example/api
```

A physical phone cannot use `localhost`, because that points to the phone. Use
the computer's reachable LAN address or the current Cloudflare Quick Tunnel URL.
An Android Studio emulator can use `http://10.0.2.2:8000/api`.

## OMR integration boundary

The verified `.pt` checkpoint remains in the Python service; it is not bundled
into Android. Mobile captures an image and uploads it to Laravel
(`POST /sheets/upload`), then polls `GET /omr-jobs/{job}`. Laravel binds the
active answer key, calls the private Python `POST /recognize` endpoint, verifies
the response, and stores answers, flags, diagnostics, and the result. Mobile
never uploads or selects an answer key.
