# Dataset Gathering Workflow

> [!info] Purpose
> Step-by-step guide for gathering the **bubble-crop dataset** that trains the OMR classifier (Phase 2 — [[AI - Task and Rules]]). Any agent picking up dataset work must follow this doc so every new sheet is captured, labeled, QA'd, and split **the same way**. Goals: **no label drift, no train/test leakage.**

---

## 1. What we are building

A labeled set of **44×44 grayscale bubble crops** to train a 3-class classifier:

| Class | Meaning |
| --- | --- |
| `shaded` | A bubble filled in (pencil/pen) |
| `empty` | An unanswered bubble (printed ring only) |
| `erasure_smudge` | Marked then erased (partial smudge) |

One physical sheet (image + truth JSON) yields **410 bubble crops** — one crop for every printed option: inductive `10×5 = 50`, plus the other sections `90×4 = 360`. The sheet still has 100 items across 5 sections: inductive 10 · math 30 · english 30 · science 20 · aptitude 10 (see [[Answer Key Format]]).

The **unit of data is the sheet**: all crops from one sheet stay together in one split (`train`/`val`/`test`), otherwise the model sees its own test answers.

---

## 2. Folder layout

```
omr/dataset/
├── raw_sheets/                      ← what we gather (source of truth)
│   ├── sheet_001.jpg                ← photo/scan of a filled answer sheet
│   └── sheet_001.json               ← ground-truth labels for that sheet
└── crops/                           ← generated by tools — NEVER hand-edit
    ├── preview/                     ← QA output + its own _manifest.csv
    │   ├── shaded/sheet_001/*.png
    │   ├── empty/sheet_001/*.png
    │   ├── erasure_smudge/sheet_001/*.png
    │   ├── _manifest.csv
    │   ├── _contact_sheet_sheet_001.png   ← label QA
    │   └── _overlay_sheet_001.png         ← alignment QA
    ├── train/<class>/sheet_id/      ← committed crops for training
    ├── val/<class>/sheet_id/
    ├── test/<class>/sheet_id/
    └── _manifest.csv                ← master index: sheet_id, split, class, path
```

- `sheet_id` **must match** the image filename stem (`sheet_005.jpg` ↔ `sheet_005.json`). Next number continues from the last existing sheet.
- Filenames carry their sheet_id, and rows live in `_manifest.csv` — training reads the manifest (`core/dataset.py::BubbleDataset`), **not** `ImageFolder`.

## 3. Per-sheet workflow (do in this order)

### Step 1 — Capture
Photo/scan of a filled sheet → `omr/dataset/raw_sheets/sheet_NNN.jpg`. Try to vary conditions (see §5) and record them.

### Step 2 — Write the truth JSON
Create the matching `sheet_NNN.json`:

```json
{
  "sheet_id": "sheet_005",
  "answer_key_id": null,
  "capture": {
    "device": "phone",
    "lighting": "indoor_uneven",
    "angle": "slight_tilt",
    "instrument": "pencil"
  },
  "items": [
    {"item": 1, "section": "inductive", "marked": "A", "state": "valid"}
  ]
}
```

- `capture` documents conditions: `device`, `lighting`, `angle`, `instrument`. Fill them in — this is how we later find which conditions the model struggles with.
- `items`: one row per question with `section`, `item` (1-based), `marked` (letter **or list of letters** for multi-mark), `state` (`valid` | `erasure` | `blank` | `multi`).
- Marked section can be omitted from the list = treated as blank/empty.

### Step 3 — Preview (NEVER skip)
```
python tools/crop_bubbles.py preview --image dataset/raw_sheets/sheet_005.jpg --truth dataset/raw_sheets/sheet_005.json
```
This SIFT-registers the sheet against `Answer_Key_Format.jpg`, adapts the per-row bubble-lattice offsets, and writes crops + QA images to `crops/preview/`.

### Step 4 — Inspect the two QA images
- `_contact_sheet_sheet_005.png` — **label QA**: do crops visually match their labels? (shaded look filled, empty look blank, erasures look smudgy)
- `_overlay_sheet_005.png` — **alignment QA**: are the red ROI circles centered on the printed bubbles?

If anything is wrong → fix the truth JSON (or recapture) → re-run preview. Only proceed when both pass.

### Step 5 — Commit to training data
```
python tools/crop_bubbles.py label --image ... --truth ... --split train
```
`--split` = `train` | `val` | `test`. Safe to re-run: it deletes this sheet's stale crops (split/class changed or truth corrected) and rewrites only this sheet's manifest rows.

### Step 6 — Rebalance splits (whole sheets only)
```
python tools/assign_splits.py --train sheet_001 sheet_002 --val sheet_003 --test sheet_004     # dry run — read the plan
python tools/assign_splits.py --train sheet_001 sheet_002 --val sheet_003 --test sheet_004 --apply   # move + update manifest
```
Always **dry-run first** (`--apply` omitted prints the plan only). Never move individual crops between splits.

## 4. Labeling rules (as implemented in `tools/crop_bubbles.py`)

Per bubble in a 44×44 crop:

| Truth state | That letter marked? | Crop class |
| --- | --- | --- |
| `erasure` | yes | `erasure_smudge` |
| anything | yes | `shaded` |
| anything | no | `empty` |

- **Multi-mark items** (`state: "multi"`, `marked: ["A","B"]`): **every filled bubble is `shaded`** — a 44×44 crop can't see neighbouring bubbles. Multi is decided later at item level by counting shaded bubbles per item.
- Classes are fixed indices in `core/dataset.py`: `("shaded", "empty", "erasure_smudge")` → 0, 1, 2.

> [!warning] Hard rules
> 1. Never hand-edit `crops/` or `_manifest.csv` — only the tools write them.
> 2. A sheet's crops live in exactly **one** split. Fix leakage via `assign_splits.py`, never by moving files manually.
> 3. Don't commit a sheet to `train/val/test` before its preview passes QA.
> 4. Keep `sheet_id`, image name, and JSON `sheet_id` identical.

## 5. What to gather next (variety checklist)

Current inventory: `sheet_001`–`sheet_025` (**25 sheets / 10,250 crops**). Whole-sheet split: train `sheet_001`–`sheet_019` (7,790 crops), validation `sheet_020`–`sheet_022` (1,230), test `sheet_023`–`sheet_025` (1,230). The priority is still **coverage of conditions + minority classes**, not bulk:

1. **Erasures & blanks** — sheets with deliberately erased answers and skipped items (critical minority classes)
2. **Lighting** — even indoor, uneven/shadowed, near-window, camera flash
3. **Angles** — flat scan, slight tilt, pronounced tilt/skew
4. **Devices** — scanner, different phone cameras (record in `capture.device`)
5. **Instruments** — pencil (light/heavy pressure), ballpoint pen, double-pressed bubbles
6. **Real-world noise** — folds/creases, finger smudges near bubbles

Log every variation in `capture` so per-condition evaluation is possible later. Aim for balanced class counts overall — track them via `BubbleDataset(split=...).class_counts()` and the manifest.

> [!warning] Current model evidence
> The local final three-class report uses the split above and records 98.29% overall test accuracy,
> 93.88% balanced accuracy, and 78.94% macro F1. Minority-class evidence remains weak: the test
> set contains only 8 `erasure_smudge` crops, with 25.93% raw-argmax precision. A production
> erasure-probability threshold of 0.80 was selected only on validation sheets 020–022; it achieves
> 97.0% exact item accuracy on locked test sheets 023–025 and 97.04% across all 2,500 existing items.
> All 10,250 production crops match the labeled crops exactly. Many truth files still record capture
> conditions as `unknown`; gather better metadata, more erasures, and new mobile-camera sheets before
> claiming broad field readiness.

## 6. Command quick reference (run from `omr/`)

| Task | Command |
| --- | --- |
| QA new sheet | `python tools/crop_bubbles.py preview --image dataset/raw_sheets/sheet_NNN.jpg --truth dataset/raw_sheets/sheet_NNN.json` |
| Commit labeled crops | `python tools/crop_bubbles.py label --image ... --truth ... --split train` |
| Move sheets between splits | `python tools/assign_splits.py --train ... --val ... --test ... --apply` |
| Load for training | `BubbleDataset("dataset/crops/_manifest.csv", split="train")` from `core/dataset.py` |
| Reproduce held-out model report | `python tools/evaluate_model.py --checkpoint models/final_three_class/best.pt --manifest dataset/crops/_manifest.csv --split test --expected-report models/final_three_class/test_report.json` |
| Validate full 25-sheet pipeline | `python tools/validate_pipeline.py --output models/final_three_class/pipeline_report.json` |
| Recognize one sheet | `python tools/recognize_sheet.py --image dataset/raw_sheets/sheet_001.jpg --output recognition.json --debug-overlay recognition-overlay.png` |
| Sheet-config sanity | see `core/sheet_config.py` (`SHEET_SECTIONS`, `OPTION_COUNT`), exposed at `GET /sheet-config` in `app.py` |
